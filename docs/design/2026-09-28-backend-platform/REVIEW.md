# Architecture review and evidence

## Scope and method

Checked 2026-09-28 in `KeepSave-landing`, branch `feat/landing-event-horizon-20260928`, base commit `9e2b3bafab76d4dc7beba478a87819e069cff34c`, including the existing uncommitted work. The canonical `KeepSave` checkout is not the implementation target of this review.

This is a repository-wide architecture review: source inventory, dependency and caller searches, route/data-model inspection, and deeper reading of credential, MCP, persistence, execution, and deployment paths. It is **not** a claim that every line received a security audit or every feature was executed. No production database, user credentials, ignored environment files, or live provider integrations were inspected.

The inventory contains 442 source/configuration/test files under the stated filter: 263 backend, 141 frontend, 7 SDK, 9 Helm, 3 integration implementations, 9 end-to-end test/support files, and 10 other workflow/script/config files. Markdown, lockfiles, media, private/ignored files, and generated build output are excluded from that count. Architecture and governance Markdown was reviewed separately. File paths, line counts, and hashes are recorded in [source-inventory.json](/mnt/data/keepsave-backend-design-2026-09-28/source-inventory.json); enumeration/hashing is not evidence of line-by-line review.

## Foundations to retain

- AES-256-GCM envelope encryption with per-project DEKs; service-secret key separation and defensive decrypt handling.
- Promotion state transitions, rollback snapshots, and database self-approval protections. Extend these through the vault mutation boundary rather than replacing them casually.
- API-key expiry and per-key scope grammar, lease-bound short-lived read tokens, and denylist/lease revocation checks.
- Structured error handling, request limits, platform-admin gating, trusted-proxy controls, negative-auth tests, and canonical audit events.
- PostgreSQL as the documented production database; SQLite test/local support and MySQL parity migrations.
- CLI and SDK clients, accepted React workspace, embed widget boundary, and existing provider-login preparation.

## Findings and required follow-through

All findings below are **observed in source**, unless explicitly described as a hypothesis. Reproduction tests are required before claiming exploitability or a completed fix. The priority is relative to enabling broader harness/credential access.

| ID / priority | Evidence and observed behavior | Required work |
|---|---|---|
| R01 / first | [CreateLease](../../../backend/internal/api/handlers_agent.go) passes `user_id` into `api_key_id`; [APIKeyAuthMiddleware](../../../backend/internal/api/middleware.go) sets that value to the key owner. The PostgreSQL lease FK references `api_keys(id)`. The request’s individual `secret_keys` are not checked against parent key globs in this creation path. Mint checks project equality but does not compare caller authority to the lease scope. | Reproduce full create→mint→read flow with real FKs and distinct user/key IDs. Use explicit principal IDs; require child permissions and expiry to be subsets of the parent. Test another key’s lease in the same project. |
| R02 / first | [MCP UpdateInstallation](../../../backend/internal/api/handlers_mcp.go) passes actor for audit; [service](../../../backend/internal/service/mcp_service.go) calls repository update without actor; [repository](../../../backend/internal/repository/mcp_repo.go) updates by installation ID alone. `GetServer` does not check owner/public status; install checks availability but lacks a project-membership/private-server decision. | Add cross-user/private-server/project-negative tests and authorization at service/repository boundaries. Treat installation and server metadata as scoped resources. |
| R03 / first | [UserHasAccess](../../../backend/internal/repository/project_repo.go) accepts any organization membership; [secret mutations](../../../backend/internal/service/secret_service.go) do not add a role decision. Organization management separately checks roles. | Publish and enforce an action-by-role matrix for every sensitive operation; project membership alone is insufficient for team governance. |
| R04 / first | [builder](../../../backend/internal/service/mcp_builder_service.go) clones a mutable branch and runs dependency/build commands in API-host processes. Several commands inherit the host environment. Build logs use unbounded `CombinedOutput`; semaphore/timeout bound some resource use but do not isolate files/network/credentials. | Disable untrusted builds in the team profile until a separate build service is available. Build without vault credentials, pin source/artifact digests, bound output and resources. |
| R05 / first | [gateway](../../../backend/internal/api/handlers_mcp_gateway.go) launches node/python directly with mapped plaintext environment values. Minimal child env, timeout, process group cleanup, output cap, and literal scrubbing exist. No OS isolation or destination policy is set here. It resolves mappings from a user-owned server definition against caller project membership, skipping failures. | Broker and authorize every required binding; missing bindings fail the call. Use isolated runners. Literal redaction cannot stop transformed secrets or network exfiltration. |
| R06 / foundation | [version repository](../../../backend/internal/repository/version_repo.go) defines `CreateVersion` with no normal application caller found. [version handler](../../../backend/internal/api/handlers_version.go) decrypts with the current DEK and skips decryption errors during listing. [backup service](../../../backend/internal/service/sso_service.go) encrypts project/count/type metadata; no restore route exists. | Atomic history, explicit corruption errors, key-compatible restore and an actual recovery bundle/drill. Existing metadata snapshots must be labeled as non-restorable. |
| R07 / foundation | [key rotation](../../../backend/internal/service/keyrotation_service.go) reads live secret rows before its transaction, re-encrypts current rows, and swaps the DEK. It does not re-encrypt version or promotion-snapshot rows. | Concurrency tests and a key-version design before adding history. Test promotion rollback and retained history after rotation. Pre-transaction read races are a hypothesis requiring reproduction. |
| R08 / foundation | [emitAudit](../../../backend/internal/service/audit_helper.go) explicitly treats audit failures as nonfatal after mutations. [audit chain](../../../backend/internal/repository/audit_repo.go) uses a process-local lock and chain tip. | Mutation+audit transaction; persisted chain head with database serialization before multiple writers. Admission audit must commit before credential release. |
| R09 / MCP | Gateway routes only `tools/call`; tool listing is a separate GET. Execution writes one JSON object to child stdin and reads until EOF. Declared transport strings do not dispatch to a remote HTTP client. Tool name collisions pick the first matching installation. | Replace the wire boundary with a pinned MCP SDK and versioned compatibility tests; stable installation/tool IDs and schema checks. Do not claim current generic client compatibility. |
| R10 / MCP | [frontend `listMCPTools`](../../../frontend/src/api/client.ts) expects `{servers}`, while the wired gateway handler returns JSON-RPC `result.tools`. Generated config names `@keepsave/mcp-client`; no implementation of that package was found in this repository. | Contract tests between real handler and client; verify package provenance/availability before any install instructions. Use the new supported endpoint directly where possible. |
| R11 / governance | `GetPolicies` is consumed by the platform listing handler; no shared policy evaluator is wired. Caller search found no production use of `IPAllowlistService.CheckIPAllowed`, plugin `ValidateAll`, event `Publish`/`Subscribe`, or agent `LogActivity`. | Inventory desired guarantees and connect them explicitly; storing/toggling a policy or plugin is not proof of enforcement. Keep optional systems outside the authorization path. |
| R12 / durability | [event bus](../../../backend/internal/events/eventbus.go) starts goroutines then marks an event published without delivery acknowledgements. [webhook service](../../../backend/internal/service/webhook_service.go) holds configurations/delivery log in memory. | Transactional outbox and durable jobs, acknowledgements, bounded retries, restart recovery. Persist webhook configuration and encrypted signing material. |
| R13 / scaling | Builder directories/semaphore, rate limiter, traces/metrics, plugin implementations and audit head are process-local. Migration startup has no deployment-level single-writer coordination. Helm includes HPA configuration. | Keep one API replica until multi-instance tests pass; separate artifact storage, durable scheduling, migration job/lock, shared admission limits and telemetry. HPA presence is not scaling evidence. |
| R14 / packaging | [backend Dockerfile](../../../backend/Dockerfile) uses a distroless runtime containing the Go binary and migrations, without git/node/python/npm. The builder and gateway depend on those executables. `resolveMasterKey` wires env/Vault; AWS/GCP selectors return deferred errors. | Capability diagnostics and separate execution images. Verify the actual selected key provider before advertising support. Do not add package managers to the vault API image as a shortcut. |
| R15 / clients | SDKs include plaintext caches and retries around mutations. CLI `run` inherits ambient env and streams child output. CI/Terraform integrations export values or write files; GitLab uses `eval`. | Explicit legacy-export mode, safer serializers, expiry-aware/no-cache strict mode, cancellation, idempotency-aware retries. These clients are not harness sandboxes. |
| R16 / optional AI | NLP supplies project/key metadata to configured providers and records user queries. Drift/recommendations use metadata summaries after local inspection. Scheduled drift currently advances by six hours rather than evaluating its cron string. | Explicit metadata-egress/retention policy, scoped read models, deterministic scheduler; advisory AI output cannot grant access or trigger changes. |

## Tests and evidence limits

The current static test inventory includes 23 API test files (66 top-level tests), 28 service test files (93 top-level tests), and 12 repository test files (27 top-level tests). These are counts, not coverage percentages. The older [test pyramid census](../../../tests/PYRAMID.md) describes a much earlier state and should not be used as a current count.

Earlier on 2026-09-28, this same working tree passed the backend suite with the race detector and `go vet`, after a 23-case secret-ID authorization regression test was added. Before the fix, nine denial cases failed. Evidence is in [backend intake validation](../../validation/2026-09-28-backend-intake/README.md) and `/mnt/data/keepsave-backend-baseline-2026-09-28/`. Those tests prove that bounded fix; they do not prove the findings above are resolved. Provider-specific tests may skip when their isolated services are absent.

This planning pass did not rerun application tests, exercise third-party MCP code, restart the preview backend, benchmark capacity, or perform an independent security review. Only documentation/inventory validation is claimed for this pass.
